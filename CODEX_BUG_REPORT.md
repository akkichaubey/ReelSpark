### Bug ID: `BUG-FNC-001`
- **Feature / Component:** AI Reel Social Media Post Copywriter  
- **Affected Files:**
  - `src/lib/social-post/copywriter.ts`
  - `src/app/api/social-copy/route.ts`
  - `src/components/social-publishing/SocialPostStudio.tsx`
- **Severity:** High
- **Steps to Reproduce:**
  1. Start the application without an `OLLAMA_API_KEY` configured in `.env.local`.
  2. Navigate to `/social-post` or trigger "Generate Social Post" from an AI clip candidate.
  3. The system prints `Ollama social generation notice, falling back to heuristics: Ollama Cloud is not configured` to the server log.
  4. The client UI renders the generated copy, but does not indicate whether it was generated by the LLM or smart local heuristics.
- **Expected Behavior:**
  When Ollama Cloud is unconfigured or unreachable, the fallback heuristics should generate the copy, and the API response should return `{ isFallback: true, provider: 'heuristic' }`. The UI should inform the user that local templates were used and offer a one-click shortcut to configure Ollama Cloud or Gemini BYOK.
- **Actual Behavior:**
  Server silently falls back without notifying the frontend UI of the fallback status.
- **Root Cause Analysis:**
  `generateSocialCopy()` in `src/lib/social-post/copywriter.ts` catches the Ollama error and resolves using heuristic rule-based templates, but omits the provider metadata in the return interface.
- **Suggested Fix for Codex:**
  ```typescript
  // In src/lib/social-post/types.ts:
  export interface SocialCopyResult {
    hooks: string[];
    descriptions: string[];
    hashtags: string[];
    callToActions: string[];
    isFallback?: boolean;
    providerUsed: 'gemini' | 'ollama' | 'heuristic';
  }
  
  // In src/app/api/social-copy/route.ts:
  return NextResponse.json({ success: true, copy: { ...result, isFallback, providerUsed } });
  ```

### Bug ID: `BUG-FNC-002`
- **Feature / Component:** Studio Shell Project Selector Navigation  
- **Affected Files:**
  - `src/components/clipping-studio/StudioShell.tsx` (Lines 475–477)
- **Severity:** Medium
- **Steps to Reproduce:**
  1. Open a project on `/clipping-studio?tab=merge` or navigate to `/auto-cut?tab=export`.
  2. Select another project from the "Project" dropdown in the studio sub-bar.
  3. Notice that the URL redirects to either the root of `/clipping-studio` or `/auto-cut`, sometimes losing the active sub-tab.
- **Expected Behavior:**
  Switching projects should maintain the user's currently selected tab (e.g. `tab=merge`, `tab=export`, or `tab=timeline`) across project switches unless the target project lacks required assets.
- **Actual Behavior:**
  The path replacement logic conditionally substitutes `/clipping-studio` with `/auto-cut` without consistently preserving secondary query parameters.
- **Root Cause Analysis:**
  In `StudioShell.tsx`:
  ```typescript
  const targetUrl = studioProjectUrl(event.target.value, tabParam || (pathname === '/auto-cut' ? 'autocut' : 'media'));
  router.push(pathname === '/auto-cut' ? targetUrl.replace('/clipping-studio', '/auto-cut') : targetUrl);
  ```
  `studioProjectUrl` constructs default query params that can overwrite specific sub-tab selections.
- **Suggested Fix for Codex:**
  Preserve `searchParams.get('tab')` directly into `targetUrl`:
  ```typescript
  const currentTab = searchParams?.get('tab') || (pathname === '/auto-cut' ? 'autocut' : 'media');
  const targetUrl = studioProjectUrl(event.target.value, currentTab);
  router.push(pathname === '/auto-cut' ? targetUrl.replace('/clipping-studio', '/auto-cut') : targetUrl);
  ```

### Bug ID: `BUG-FNC-003`
- **Feature / Component:** Multi-Track Timeline Audio Detach & Re-link Gain Sync  
- **Affected Files:**
  - `src/components/caption-maker/ProfessionalTimeline.tsx`
  - `src/lib/caption-maker/timeline-bridge.ts`
- **Severity:** High
- **Steps to Reproduce:**
  1. In AI Reel Maker (`/reel-maker`), open a project with a video that has an embedded audio track.
  2. Right-click the video clip and select "Detach Audio".
  3. A new audio clip appears on Audio Track 1. Adjust its volume gain slider to `+4.0 dB`.
  4. Right-click and choose "Re-link Audio to Video".
  5. The detached audio clip is removed, and the video clip re-links its audio, but the volume resets to `0.0 dB` (original gain).
- **Expected Behavior:**
  When re-linking a detached audio track to its parent video track, any mutated audio parameters (`gainDb`, `muted`, `denoise`) should be written back to the video clip's audio settings.
- **Actual Behavior:**
  Audio gain resets to default upon re-linking.
- **Root Cause Analysis:**
  The re-linking function in `timeline-bridge.ts` discards the detached audio track node and restores the video clip's original embedded audio descriptor without copying over the detached track's runtime modifications.
- **Suggested Fix for Codex:**
  ```typescript
  // In timeline-bridge.ts re-link handler:
  const detachedTrack = timeline.tracks.find(t => t.id === detachedTrackId);
  const detachedClip = detachedTrack?.clips.find(c => c.linkedVideoClipId === videoClip.id);
  if (detachedClip) {
    videoClip.audioGainDb = detachedClip.audioGainDb ?? 0;
    videoClip.audioMuted = detachedClip.muted ?? false;
  }
  ```

### Bug ID: `BUG-FNC-004`
- **Feature / Component:** Word-Level Acoustic Timing Overlap on Rapid Speech  
- **Affected Files:**
  - `src/lib/caption-maker/acoustic-aligner.ts`
  - `src/lib/caption-maker/caption-grouping.ts`
- **Severity:** Medium
- **Steps to Reproduce:**
  1. Upload audio containing very rapid spoken words (>4.5 words/second, typical in auctioneer clips or fast Hindi YouTube intros).
  2. Run AI audio transcription with word-level sync.
  3. Open the "Word-Level Timing Adjustment Studio".
  4. In certain intervals, two adjacent words have identical start and end timestamps (`startMs == endMs`).
- **Expected Behavior:**
  Every word must have a guaranteed non-zero duration (at least 80ms) and no overlapping intervals.
- **Actual Behavior:**
  Overlaps are clamped to `0ms` when speech duration between word centers is negligible.
- **Root Cause Analysis:**
  `acoustic-aligner.ts` resolves overlaps by executing:
  ```typescript
  if (current.startMs < previous.endMs) {
    previous.endMs = current.startMs;
  }
  ```
  If `current.startMs <= previous.startMs`, `previous.endMs` becomes `<= previous.startMs`, causing duration to collapse to zero or negative.
- **Suggested Fix for Codex:**
  Enforce a minimum floor constraint:
  ```typescript
  const MIN_WORD_DURATION_MS = 80;
  if (current.startMs < previous.endMs) {
    const midpoint = Math.floor((previous.endMs + current.startMs) / 2);
    if (midpoint - previous.startMs >= MIN_WORD_DURATION_MS) {
      previous.endMs = midpoint;
      current.startMs = midpoint;
    } else {
      previous.endMs = previous.startMs + MIN_WORD_DURATION_MS;
      current.startMs = Math.max(current.startMs, previous.endMs);
    }
  }
  ```

### Bug ID: `BUG-FNC-005`
- **Feature / Component:** Merge Studio Lossless Stream Copy Audio Sample Rate Concat Failure  
- **Affected Files:**
  - `src/lib/ffmpeg.ts` (`mergeClipsStreamCopy`)
  - `src/app/api/clipping-studio/export/route.ts`
- **Severity:** High
- **Steps to Reproduce:**
  1. In Clipping Studio, import two videos recorded on different devices (e.g. Video 1 with 44.1kHz AAC audio and Video 2 with 48kHz AAC audio).
  2. Create a Merge Recipe containing both clips.
  3. Select the "Instant Copy (Lossless Stream Copy)" preset.
  4. Start the export.
  5. The export fails with FFmpeg error: `[concat @ 0x...] Non-matching audio sample rates (44100 vs 48000) not supported in stream copy`.
- **Expected Behavior:**
  The export engine should detect stream compatibility prior to executing `-c copy`. If sample rates or codecs differ, it should either auto-transcode audio only (`-c:v copy -c:a aac -ar 48000`) or notify the user to use the High Fidelity Transcode preset.
- **Actual Behavior:**
  FFmpeg terminates with exit code 1 and marks the job as failed in Export Queue.
- **Root Cause Analysis:**
  `mergeClipsStreamCopy()` builds an FFmpeg concat demuxer text file and passes `-c copy` unconditionally without validating stream metadata parity between source clips.
- **Suggested Fix for Codex:**
  In `src/lib/ffmpeg.ts`:
  ```typescript
  export async function validateStreamCopyParity(clipPaths: string[]): Promise<boolean> {
    const probes = await Promise.all(clipPaths.map(p => probeMedia(p)));
    const sampleRate = probes[0].audio?.sampleRate;
    const channels = probes[0].audio?.channels;
    const vCodec = probes[0].video?.codec;
    return probes.every(p => 
      p.video?.codec === vCodec &&
      p.audio?.sampleRate === sampleRate &&
      p.audio?.channels === channels
    );
  }
  // If false, switch FFmpeg command from `-c copy` to `-c:v copy -c:a aac -b:a 192k -ar 48000`.
  ```

### Bug ID: `BUG-FNC-007`
- **Feature / Component:** Cloudflare D1 / SQLite Parallel Mutation Contention on Batch Candidate Saves  
- **Affected Files:**
  - `src/lib/clipping-studio/project-bridge.ts`
  - `src/app/api/projects/[id]/route.ts`
- **Severity:** Medium
- **Steps to Reproduce:**
  1. Open a project with 25 AI clip candidates.
  2. Click "Select All", then click "Save Selected to Library".
  3. The frontend triggers 25 concurrent `handleSaveCandidateToLibrary()` calls.
  4. In local development or heavy server load, some requests return 500 with `SQLITE_BUSY: database is locked`.
- **Expected Behavior:**
  Batch saves should either execute sequentially with a concurrency limiter or hit a dedicated batch API endpoint in a single atomic database transaction.
- **Actual Behavior:**
  Parallel asynchronous requests compete for SQLite database write locks.
- **Suggested Fix for Codex:**
  Create a single batch update route `POST /api/projects/[id]/candidates/batch-save` that accepts `candidateIds: string[]` and wraps the D1 inserts in a single transaction:
  ```typescript
  await db.batch(candidateIds.map(id => db.prepare('UPDATE candidates SET savedReelId = ? WHERE id = ?').bind(reelId, id)));
  ```

### Bug ID: `BUG-FNC-008`
- **Feature / Component:** Remotion React Canvas Re-render Lag on Heavy Multi-Asset Compositing  
- **Affected Files:**
  - `src/components/caption-maker/RemotionPlayerPreview.tsx`
  - `src/remotion/Root.tsx`
- **Severity:** Medium
- **Steps to Reproduce:**
  1. Build a complex 60-second reel with 15+ B-roll cutaway segments, animated emojis, full-screen background video, and active waveform bars.
  2. Play the reel in the editor preview.
  3. On machines without dedicated GPUs, playback framerate drops below 20 FPS during preview.
- **Expected Behavior:**
  Preview should play smoothly by memoizing inactive video segments and downscaling preview buffer resolution during live scrubbing.
- **Actual Behavior:**
  Every frame tick recalculates all layers and active DOM nodes across all tracks.
- **Suggested Fix for Codex:**
  In `RemotionPlayerPreview.tsx`:
  - Enable `playbackRate={1}` and configure Remotion's `numberOfSharedAudioTags={4}`.
  - Wrap overlay stickers and static graphic components with `React.memo()`.
  - Add an optional "Preview Resolution" toggle (1080p, 720p, 540p) that scales the canvas render buffer down during timeline playback.
